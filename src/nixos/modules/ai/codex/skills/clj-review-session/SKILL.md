---
name: clj-review-session
description: Perform the clj-code-review workflow and report its findings as anchored shared threads in the user's specified local review session, with one review-level coverage record.
---

Layer this destination contract on the existing [clj-code-review skill](../clj-code-review/SKILL.md); read and follow that skill rather than replacing or duplicating its review process. Also read the installed `review-session` CLI skill from the skill catalog, or `${CODEX_HOME:-$HOME/.codex}/skills/review-session/SKILL.md`.

- Require the explicitly specified session path in addition to the review target/base, intended behavior, scope, source access and notes path. A `session.sqlite3` file path selects its parent directory. If required scope/session information is missing, obtain it before writing findings; do not choose a different active workspace.
- Preserve the independent reviewer handoff required by clj-code-review. Include both skill instructions and the exact session path in that handoff. If already the delegated reviewer, perform the review without another handoff. Keep the guidance record and evidence-backed coverage checklist in the review notes as required by the base skill.
- For each concrete finding, create a separate **shared agent thread** through `review-session --session SESSION --role agent create`. Anchor it to the review's actual repository, base and target versions, path and old/new side/range where applicable. Use file or review scope when no honest source range applies. Include evidence, consequence, severity and uncertainty in the finding body; preserve immutable original context instead of anchoring a historical finding to the current checkout. Reuse an existing thread only when it is demonstrably the same finding at the same original pair.
- Once the review is complete, append one review-level `coverage --target REVIEW_LABEL --body-file FILE` record containing target/base, intended behavior, guidance used and the final completed/inapplicable/unverified checklist. Do not duplicate that checklist in each finding. Zero findings still requires the coverage record; thread resolution does not prove a check was completed.
- Read back the created threads and coverage record and verify their IDs, visibility, original coordinates and bodies. If a CLI write or stale-anchor guard fails, preserve the finding text and report the failure explicitly. Finish with the session path, finding thread IDs and a link to the review notes, plus unresolved concerns and actual verification limits.
- This workflow records local review output only. It does not authorize remote publication, source changes, session deletion or marking files reviewed merely because they were browsed. Keep the base skill's critical review judgment; do not invent findings to fill a quota.
